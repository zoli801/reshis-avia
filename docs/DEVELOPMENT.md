## Среда и команды

Для воспроизводимого запуска используйте Node.js **26.5.0** и зафиксированный `package-lock.json`.

| Команда | Действие |
| --- | --- |
| `npm run install:ci` | Установка зависимостей из lock-файла с учётом среды. |
| `npm run setup:local` | Подготовка локального окружения без перезаписи существующих секретов. |
| `npm run build` | Сборка клиента и Worker в `dist/`. |
| `npm run db:migrate` | Применение SQL-миграций к локальной D1. |
| `npm run dev` | Разработка на loopback-адресе, по умолчанию порт 5173. |
| `npm start` | Проверка собранного Worker с локальными D1/R2. |
| `npm run typecheck` | Проверка TypeScript. |
| `npm test` | Автотесты без настоящих секретов и запросов в Telegram. |

Первая подготовка: установка → локальное окружение → сборка → миграции → сервер разработки. При изменении привязок ресурсов повторите сборку. Файлы в `.wrangler/`, `.sites-runtime/`, `dist/` и локальные переменные окружения не публикуются.

В переносимом режиме разработки Sites предоставляет **тестовую идентичность ChatGPT**. Это локальная эмуляция. Настоящий вход ChatGPT использует доверенный шлюз Sites и верхнеуровневые переходы `/signin-with-chatgpt` и `/signout-with-chatgpt`.

## Серверные настройки

`.openai/hosting.json` в публичном проекте содержит только привязки ресурсов и возможности приложения. Идентификатор чужой production-публикации и значения секретов для запуска не нужны.

| Ключ | Назначение |
| --- | --- |
| `PASSWORD_PEPPER` | Случайный серверный секрет проверки паролей. Нужен для регистрации и входа по паролю. |
| `BOT_TOKEN` | Секрет Telegram-бота. Задаётся только на сервере при подключении реального бота. |
| `BOT_ID`, `BOT_USERNAME` | Идентификатор и публичное имя подключаемого бота. |
| `TELEGRAM_WEBHOOK_SECRET` | Отдельный секрет проверки webhook Telegram. |
| `BOT_INTERNAL_SECRET` | Защита служебных методов бота. |
| `WEBAPP_URL`, `PUBLIC_URL` | HTTPS-адрес собственной публикации. |
| `SITE_OWNER_EMAIL` или `ADMIN_EMAIL` | Подтверждённый владелец административного профиля ChatGPT. |
| `ADMIN_TELEGRAM_ID` | Необязательный заранее проверенный числовой Telegram ID владельца. |

Не заменяйте `PASSWORD_PEPPER` при каждом развёртывании: существующие проверки паролей зависят от него. При отсутствии секрета вход по паролю безопасно отключается; остальные настроенные способы входа продолжают работать.

Для гостевого режима, расчётов и автотестов настоящий токен Telegram не требуется. Не передавайте секреты в параметры URL, клиентский код, публичные конфигурации или сообщения об ошибках.

## Расчётное ядро и данные

Основная функция — [`evaluate`](../lib/aviation/domain.ts). Она получает строку рейса, параметры направления, цену и необязательные экспериментальные условия.

```text
спрос(q) = base_demand(q) − price_sensitivity × (цена − base_price)
продажи(q) = min(seats, max(0, спрос(q)))
свободные места(q) = seats − продажи(q)
выручка(q) = цена × продажи(q)
маржинальный доход(q) = (цена − cost_per_passenger) × продажи(q)
```

Основные показатели берутся из P50. Отрицательный спрос сохраняется как оценка линейной модели, а продажи ограничиваются нулём и вместимостью. Дробные значения являются прогнозами; округление используется для отображения.

Все девять `base_demand` пересчитываются при **одной цене**. Поля `q_price_demand` относятся к разным оптимальным ценам и не подменяют распределение при цене пользователя. Показанный график соединяет известные квантили и не является плотностью распределения.

Рекомендованная цена максимизирует маржинальный доход по медиане в допустимых границах с учётом вместимости. Постоянные расходы рейсов не учитываются. Экспериментальные параметры явно отмечены и не изменяют исходный CSV.

Исходный прогноз: 155 записей, пять маршрутов, 31 дата. SHA-256 CSV:

```text
40dc4508cbde3413ee21286f6e8884bb1a0844dca80d61befaccc295168a075a
```

Первый запрос к данным пустой базы создаёт исходную версию из `lib/aviation/seed.ts` после применения миграций. Дальше API использует активную версию D1. Для отсутствующих маршрутов или дат возвращается ошибка, новые прогнозы не выдумываются.

## Хранение и версии

- **D1:** профили, хеши сессий, версии данных, сценарии, настройки, очередь уведомлений и журнал действий.
- **R2:** исходные CSV новых импортов.
- **Сценарий:** результат, альтернативные цены, обоснование, статус и версия исходных данных.

Импорт проверяет структуру CSV, даты, числа, уникальность пар «маршрут/дата» и порядок квантилей. Новая активная версия не меняет ранее сохранённые отчёты. Размер одного загружаемого файла ограничен 10 МБ; разобранные данные одной записи D1 — 1,8 МБ.

Миграции находятся в `drizzle/` и применяются последовательно. Не удаляйте пользовательские таблицы для обновления приложения.

## Аккаунты и роли

Гостевой профиль позволяет сохранять решения без регистрации. Он привязан к защищённой cookie браузера; очистка cookie прекращает доступ к гостевым сохранениям. Регистрация и вход добровольны.

| Способ | Проверка личности |
| --- | --- |
| Логин и пароль | Нормализованный уникальный логин, соль, PBKDF2, серверный pepper и лимиты попыток. |
| ChatGPT | Подтверждённая идентичность от шлюза Sites. |
| Telegram на сайте | Одноразовый запрос на пять минут, отдельный секрет браузера и кнопка подтверждения в личном чате бота. |
| Telegram Mini App | Проверка подписи `initData`, идентификатора бота и срока действия. |

В локальном режиме ChatGPT может эмулироваться. Самостоятельный публичный Worker без доверенного шлюза Sites не эквивалентен этой публикации: заголовки идентичности нельзя принимать от произвольного клиента.

Роли: аналитик работает со своими сценариями; руководитель согласует решения; администратор управляет данными и ролями. Имя, логин и самостоятельно введённый адрес почты не предоставляют административных прав.

Владелец может войти через свой ChatGPT и явно связать собственный Telegram одноразовой ссылкой. Это даёт подтверждённому Telegram доступ к тому же административному профилю. У остальных пользователей такой переход не повышает роль.

Сайт и Mini App имеют независимые сессии. Перенос гостевых сценариев и связывание Telegram выполняются только после явного выбора. При смене пароля прежние сессии отзываются; версия credentials защищает от восстановления сеанса конкурентным запросом со старым паролем.

В D1 находятся хеши непрозрачных токенов сессий. Cookie используют `HttpOnly`, `Secure` и отдельные пространства сайта/Mini App. Изменяющие запросы проверяются на источник; права и владение проверяются сервером.

## Основные API

| Метод | Назначение |
| --- | --- |
| `GET /api/health`, `/api/meta` | Состояние и паспорт активного прогноза. |
| `POST /api/forecast`, `/api/analytics` | Основной расчёт и аналитика периода. |
| `GET /api/overview` | Обзор направлений. |
| `/api/auth/*` | Гость, регистрация, вход, смена пароля и выход. |
| `/api/scenarios` и карточки по ID | Сохранение, согласование, CSV и печатные отчёты. |
| `/api/datasets` | Версии прогнозов. |
| `/api/notifications` | Персональные настройки подписок. |
| `/api/admin/*` | Импорт, роли и журнал. |
| `POST /api/telegram/webhook` | Проверенные обновления Telegram. |
| `/mcp` | Административные инструменты очереди уведомлений. |

API использует ограничение размера запросов, проверку параметров, SQL-привязки и безопасные сообщения об ошибках. Отчёты экранируют пользовательский текст, CSV защищает текстовые поля от формул. Ссылки на документы не обходят проверку владельца.

## Telegram и уведомления

Бот обрабатывает команды, прогнозы, сохранённые сценарии и сводки в том же Worker. Mini App использует общий интерфейс и расчётное ядро. Для реального подключения задайте серверные настройки собственного бота, HTTPS-адрес приложения и защищённый webhook `/api/telegram/webhook`.

Подписки на изменение прогноза и ежедневную сводку включаются отдельно. Пользователь выбирает направления, порог изменения загрузки, часовой пояс и тихие часы. `/stop` отключает подписки и удаляет ожидающие сообщения пользователя.

**Автоматическая периодическая отправка требует отдельно подключённого планировщика.** Функции очереди не означают, что расписание уже активно. Инструменты `notification_status` и `process_notifications` доступны только администратору. Неопределённый сетевой исход отправки не повторяется автоматически, чтобы снизить риск дублей.

## Развёртывание

Штатная публикация выполняется через Sites с ресурсами `DB` (D1) и `BUCKET` (R2). Для новой публикации платформа создаёт собственный идентификатор проекта; публичная копия не содержит доступа к работающему сайту автора.

При развёртывании примените миграции, настройте серверные секреты и проверьте публичный адрес, методы входа и webhook. Отдельно подключите планировщик, если нужны автоматические рассылки. Сборка сама по себе не публикует проект.
